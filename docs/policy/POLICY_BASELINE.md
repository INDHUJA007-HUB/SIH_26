## Synthetic process template

DRAFT → SUBMITTED requires institution authority and freezes the revision. SUBMITTED → SCREENED requires completed preliminary run. SCREENED → OFFICER_REVIEW requires assignment. OFFICER_REVIEW → AWAITING_RESPONSE requires an approved process-policy version and specified slots/fields/deadline/round. RESPONSE_SUBMITTED → REASSESSMENT freezes response facts. READY_FOR_AUTHORITY/CLOSED require the competent-authority process, never a machine score.

Allowed synthetic response example: replace one requested fire-certificate slot. Forbidden example: modifying approved intake, adding unrelated programme changes or reopening an expired/revoked window. All post-submission corrections are new versions. No real statutory deadline is inferred from the demo.

## Rule approval checklist

1. Exact source bytes/hash and clause/printed/PDF locator captured.
2. Applicability/cycle/effective date and supersession checked.
3. Ambiguity, input basis, units, precision and rounding approved.
4. Golden, boundary, unknown and benign fixtures pass.
5. Candidate impact evaluated on frozen packets.
6. Distinct authorized author/approver bind decisions to exact hash.
7. Publication, rollback and historical replay evidence retained.

Regulatory approver/process owner: role required; human designation/sign-off pending. The engineering template is selected for synthetic development only.
